# 初始化与配对比较的限制

优化器和结构归因需要区分两类实验：均值梯度对照，以及保存了共同初始化与采样记录的配对设计对照。

## 均值梯度对照

Original/MG与Full-no-PCGrad的相关运行在模型构造后才设置训练随机种子。Full-no-PCGrad入口先构造模型，再进入调用`seed_everything`的训练函数。18个结果记录均缺少`initialization`字段，记录的runner SHA-256与核查版本一致。

训练前设置seed可以固定后续采样，但不能追溯固定已经生成的初始参数。因此，这些对照的分数可以作为运行结果报告，PCGrad的独立贡献则受到初始化记录不足的限制。

## 配对设计对照

72个运行的[初始化记录](SOURCE_ARTIFACT_INDEX.md#src-1fabee06c4396b33)与[采样记录](SOURCE_ARTIFACT_INDEX.md#src-61c9754e717b991d)显示：

- 18/18折中，四臂共享骨干的初始哈希一致。
- Full与strict-shared的完整初始状态哈希一致。
- 四臂的采样与PCGrad顺序一致。
- 每臂记录2,048个源minibatch和410项投影顺序。

这些结论来自保存的运行记录及规范JSON哈希，与独立审计一致。模型在CPU `fork_rng`环境中按seed构造，再替换关系层或加入融合层；训练入口另行重置随机状态。不同变体包含不同形状或额外参数，因此比较的是共享骨干及对应配对模型的初始化。

## 适用范围

均值梯度运行的记录缺口不影响上述已保存哈希的配对设计证据。配对设计结果可以用于解释固定协议下的结构差异，但GPU轨迹不保证逐位确定，18个city×seed折也不是18个独立城市。

已有材料无法恢复未保存的初始状态。进一步开展优化器析因时，需要在构造模型前固定seed，保存共同初始参数并成对训练。

详细来源见[初始化审计记录](SOURCE_ARTIFACT_INDEX.md#src-0a98d23b2ddbd0ba)。
